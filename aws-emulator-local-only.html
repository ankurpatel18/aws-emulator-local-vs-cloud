Prepare the lab

Start Docker Desktop. Install Python 3 and AWS CLI if they are missing.

Get the source from the GitHub repository using Code → Download ZIP, or use the source folder included with this HTML in the complete lab ZIP. Open two Terminal windows in the project folder containing Dockerfile.aws-emulator and scripts/test-emulator.sh.

Check prerequisites

python3 --version
aws --version
02

Build and start the emulator

Terminal 1 · Run from the lab folder. Leave this window running during the tests.

The build selects the emulator package for Apple silicon or Intel. If your emulator is already running on port 9297, continue to Step 3.

Terminal 1 
(
  set -eu
  case "$(uname -m)" in
    arm64|aarch64)
      docker build --platform linux/arm64 --build-arg EMULATOR_RPM_ARCH=aarch64 \
        -f Dockerfile.aws-emulator -t aws-emulator .
      ;;
    x86_64)
      docker build --platform linux/amd64 -f Dockerfile.aws-emulator -t aws-emulator .
      ;;
    *)
      printf '%s\n' 'Unsupported CPU architecture.' >&2
      exit 1
      ;;
  esac
  mkdir -p "$HOME/.aws/emulator"
  docker run --rm -p 127.0.0.1:9297:9297 \
    -e HOME="$HOME" \
    -v "$HOME/.aws/emulator:$HOME/.aws/emulator" \
    aws-emulator -p 9297
)

The port mapping binds to loopback on your Mac.

      Troubleshoot a failed setup
      
NoCredentialsError · Paste the complete Step 4 block. The endpoint and generated credentials loaded by source are scoped to that block. Running a bare pytest command afterward can lose both.

      
Connection refused or missing files · Check Terminal 1 for a startup error, and confirm the container and script both use port 9297.

      
Certificate error · Restart the emulator if needed and rerun Step 3 so the command uses the generated CA for the current instance.

      
HTTP 501 / NotImplemented · Record the operation and output as blocked. Local coverage varies by feature and release. Check the AWS Emulator fidelity guide for your version.
